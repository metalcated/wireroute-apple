# WireRoute Security Policy

## Reporting a Vulnerability

Please do not disclose a suspected vulnerability or exploit details in a public GitHub issue.

Use GitHub's [private vulnerability reporting form](https://github.com/metalcated/wireroute-apple/security/advisories/new). A GitHub sign-in is required. If the private form is unavailable, open a minimal [support issue](https://github.com/metalcated/wireroute-apple/issues/new) asking the maintainer to establish a private contact channel, without including technical details or sensitive data.

Include the affected WireRoute version, platform, impact, reproduction conditions, and a suggested remediation if available. Never include live private keys, RouterOS passwords, or production tunnel configurations; use generated test credentials and documentation-only addresses.

## Supported Versions

Security fixes target the current development branch and the most recent published App Store version. Older builds may be asked to update before a report is investigated.

## Scope

The policy covers WireRoute's iOS and macOS applications, network extensions, routing logic, local credential handling, and RouterOS integration. Problems in a user-operated VPN endpoint, RouterOS installation, Apple platform, or unrelated third-party service should be reported to that project's owner.
